# Slack レポートルール

- Slack への投稿は必ず `scripts/slack_report.py` 経由で行う。`curl` 等で Webhook を直接叩かない（`guard_bash.py` がブロックする）。
- 投稿前に必ず **dry-run（`--send` なし）** でメッセージ内容を確認する。`--send` は dry-run の内容をユーザーが確認した後、または `scripts/run_monthly.sh` からの自動実行時のみ。
- Webhook URL は環境変数 `SLACK_WEBHOOK_URL`、または Secrets Manager（`SLACK_WEBHOOK_SECRET_ID`）から取得する。コード・設定ファイル・ログに書かない。

## 予算判定（scripts/slack_report.py が計算）
判定は「現状維持の予測」と「改善策実施後の予測」の2段階で行う。

| 判定 | 条件 |
|---|---|
| ✅ OK | 予測上限（high）≦ 予算 |
| ⚠️ 注意 | 予測値 ≦ 予算 < 予測上限 |
| 🚨 超過見込み | 予測値 > 予算 |

| 現状維持 | 改善策実施後 | Slack 上の動き |
|---|---|---|
| ✅ | — | 通常レポートのみ |
| ⚠️ / 🚨 | ✅ / ⚠️ | コスト消費元＋改善策を提示し、**施策の実施判断** を依頼 |
| 🚨 | 🚨 | コスト消費元＋改善策を提示し、**施策の実施判断＋残る不足分の修正稟議** を依頼（ボタン・稟議下書き付き） |

- 🚨 のとき `optimization.json` が無ければ `slack_report.py` は終了コード 3 で止まる（改善策の提示は必須）。
- 施策の年度内削減額 = Σ 月額削減 × 実施月〜年度末の月数 × (1 + `tax_rate`)。
- 修正後予算の推奨額 = `max(施策後の予測上限, 施策後の予測値 × (1 + buffer_ratio))` を 100 USD 単位で切り上げ。
- 予算・税率・メンション先・稟議フォーム URL は `config/budget.json` で管理する。ハードコードしない。

## レポート構成（順番固定）
1. ヘッダー: 対象月・データ確定/速報の別
2. 当月利用額（前月比）
3. 年度累計・予算消化率・経過月数
4. 年度着地予測（現状維持・レンジ）と予算差額、判定
5. サービス別 Top5
6. 予測根拠（forecast.json の rationale）
7. （⚠️/🚨 のみ）コスト消費元 Top5（使用タイプ単位の実績額＋所見）
8. （⚠️/🚨 のみ）改善策（削減額・開始月・リスク・対象リソース数・オーナー・判断者）
9. （⚠️/🚨 のみ）前回施策の実施状況、施策実施後の着地予測、予算内に収めるための月額上限
10. 依頼ブロック（施策の実施判断 ／ 修正稟議）
