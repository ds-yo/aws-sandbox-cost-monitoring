# progress.md 更新ルール

`progress.md` は会話履歴が無くても作業を再開するための唯一の拠り所。**問い合わせへの対応で何かが変わったら、その応答を終える前に必ず更新する。**

## 更新が必要なとき
次のいずれかがあった応答では更新する（ファイル変更の有無に関係なく）。
- ファイルを作成・変更した（コード、設定、ルール、スキル、`out/` のレポート）
- ユーザーが方針・要件・設定値を決めた、または変更した（例: 予算額、判定方針）
- 調査で新しい事実が分かった（例: AWS 環境の制約、権限の有無）
- ユーザーに質問をして回答待ちになった、または回答をもらった
- タスクが完了した、または中断・却下された

質問への回答だけで、何も変わっていない場合は更新しない。

## 書き方
- **現在地**: 常に最新の状態に書き換える（3〜5行）。何が終わっていて、何で止まっているか。
- **完了**: 日付の見出しの下に `- [x]` で追記する。
- **意思決定ログ**: `- YYYY-MM-DD: 決定内容（理由）` の形で追記する。ユーザー指示による決定は **（ユーザー指示）** と明記する。過去のエントリは書き換えない（誤りの訂正は新しいエントリで行う）。
- **次セッションの対応事項**: 完了したものは消し、新しいものを足す。ユーザーの回答待ちは **ユーザーの回答待ち** と書いて先頭に置く。SessionStart フックがこの節を読み込むので、古い内容を残さない。
- 日付は絶対日付（YYYY-MM-DD）で書く。「今日」「先週」は使わない。
- 詳細な分析結果は `out/<YYYY-MM>/` などの別ファイルに書き、progress.md からはパスで参照する。
- シークレット（キー、Webhook URL、トークン）は書かない。

## 例外
- `scripts/run_monthly.sh` からの自動実行（`AUTO_SEND=1`）では編集しない。提案があれば最終出力に書く。

## 強制
`.claude/hooks/progress_check.py`（Stop フック）が、progress.md より新しい変更ファイルを見つけると終了をブロックする。ブロックされたら progress.md を更新する。
